| `calibration/pix.toml` | Alvos de calibração (versionado, pequeno) | gerado pelo script acima |

Nota técnica: o servidor Olinda devolve HTTP 500 para `$skip`; o script faz uma única
requisição com `$top` grande e aborta se o resultado puder ter sido truncado.

### Rodar em dados reais de pagamentos

`loopsettle bound <arquivo.csv>` e `loopsettle settle <arquivo.csv>` rodam o LoopSettle num
arquivo de pagamentos reais sem carregá-lo inteiro na memória e sem enviar nada para fora da
máquina. Colunas obrigatórias (em qualquer ordem; as demais são ignoradas): `time` (segundos desde o
início do período, `HH:MM:SS[.fff]`, ou `t_ms` em milissegundos), `from`, `to` e `amount` (decimal
em unidades da moeda). O arquivo precisa estar ordenado pelo horário. A saída vai para
`loopsettle-out/<nome>/` e tem só agregados; `--per-participant` acrescenta uma linha por participante
(rótulos `P001`, `P002`... no lugar dos identificadores do arquivo, a menos de `--keep-names`; recusado
para arquivos com menos de 5 participantes, ajustável com `--min-participants`). `--report` gera
`report.md` e `report.pt-BR.md`: um relatório com os agregados, o teto de economia por prazo e como
lê-lo, que identifica o arquivo só por um hash.
Exemplo sintético: [`samples/payments_example.csv`](samples/payments_example.csv), gerado por
`loopsettle export baseline samples/payments_example.csv --payments 5000 --participants 20`.

### Validação externa (Fase 8): transferências on-chain de stablecoins

O comando abaixo roda a escada de circularidade (Hodge / CDFD / ciclos) em **qualquer**
lista de transferências no formato `from,to,amount` (com cabeçalho), lendo em streaming:

```
cargo run --release -p loopsettle-cli -- topology caminho/para/transferencias.csv
```

Fontes públicas possíveis para uma amostra pequena (ex.: um dia de transferências de USDC
entre os 200 endereços mais ativos), a escolher pelo revisor:

- conjunto público `crypto_ethereum.token_transfers` do Google BigQuery
  (filtrar por `token_address` do USDC e por um intervalo de blocos);
- a API de um explorador de blocos (normalmente exige uma chave gratuita).

Depois de exportar, renomeie as colunas para `from,to,amount` (valor em unidades do token).
**Status:** comando implementado e testado no caso do triângulo; a amostra on-chain ainda
não foi baixada (requer escolher a fonte e, possivelmente, uma chave de API).

## English

**Public** and **synthetic** data only. Large raw data are not versioned
(`data/raw/` is in `.gitignore`).

| File | What it is | How to generate |
|---|---|---|
| `fetch_pix.py` | Downloads Pix aggregates (BCB Olinda API) | `python data/fetch_pix.py --month 202609 --keys-date 2026-09-30` |
| `calibration/pix.toml` | Calibration targets (versioned, small) | generated by the script above |
| `raw/` | Raw API responses (not versioned) | generated by the script above |
| `samples/triangle.csv` | Fixed triangle case for the `topology` command | — |
| `samples/payments_example.csv` | Synthetic payment file to try `bound`/`settle` | `loopsettle export` |

Technical note: the Olinda server returns HTTP 500 for `$skip`; the script makes a single request
with a large `$top` and aborts if the result may have been truncated.

### Running on real payment data

`loopsettle bound <file.csv>` and `loopsettle settle <file.csv>` run LoopSettle on a real payment
file without loading it whole into memory and without sending anything off the machine. Required
columns (any order; others are ignored): `time` (seconds since the start of the period,
`HH:MM:SS[.fff]`, or `t_ms` in milliseconds), `from`, `to` and `amount` (a decimal in currency
units). The file must be sorted by time. Output goes to `loopsettle-out/<name>/` and contains
aggregates only; `--per-participant` adds one row per participant (labels `P001`, `P002`... instead of
the file's identifiers unless `--keep-names`; refused for files with fewer than 5 participants,
adjustable with `--min-participants`). `--report` writes `report.md` and `report.pt-BR.md`: a report
with the aggregates, the saving ceiling per deadline and how to read it, which identifies the file
only by a hash. Synthetic example:
[`samples/payments_example.csv`](samples/payments_example.csv), generated by
`loopsettle export baseline samples/payments_example.csv --payments 5000 --participants 20`.

### External validation (Phase 8): on-chain stablecoin transfers

The command below runs the circularity ladder (Hodge / CDFD / cycles) on **any** list of
transfers in `from,to,amount` format (with a header), reading it in streaming:

```
cargo run --release -p loopsettle-cli -- topology path/to/transfers.csv
```

Possible public sources for a small sample (e.g. one day of USDC transfers among the 200 most
active addresses), to be chosen by the reviewer:

- the public `crypto_ethereum.token_transfers` dataset on Google BigQuery (filter by the USDC
  `token_address` and a block range);
- a block explorer API (usually requires a free key).

After exporting, rename the columns to `from,to,amount` (amount in token units).
**Status:** the command is implemented and tested on the triangle case; the on-chain sample has
not been downloaded yet (it requires choosing the source and possibly an API key).
