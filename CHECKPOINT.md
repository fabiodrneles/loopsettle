## Phase history

- [x] Phase 0 — Environment
- [x] Phase 1 — Settlement core
  - Done: `types`, `ledger` (cents, no negative balance, atomic batch), `SettlementEngine`
    trait + `GrossRealTime`, `drive()` (streaming, several engines in one pass), `FlowStats` (UB,
    LB, potential capacity, pair matrix), `RunMetrics` + log-linear delay histogram, in-house
    PRNG + alias table, JSON writer.
  - Test: `cargo test -p loopsettle-core` (11 tests; invariants 1, 3, 7 by proptest; worked
    example in [`docs/METHODOLOGY.md`](docs/METHODOLOGY.md)).
- [x] Phase 2 — Topology
  - Done: `FlowGraph` (gross/net), hand-written CSR + CG, Hodge (B1, matrix-free B2, triangle
    limit), cycle netting (current-arc DFS), maximum CDFD (exact min-cost flow), `analyze()` →
    gross and net ladder + potential × position correlation.
  - Test: `cargo test -p loopsettle-topology` (invariants 2, 5, 6, 8; CDFD = `minilp` on 1,000
    graphs; acyclic directional part).
  - Benchmark: `cargo run --release -p loopsettle-topology --example bench_topology`.
  - Pending (D6): proportional/local CDFD variant.
- [x] Phase 3 — Synthetic generator and streaming
  - Done: `ScenarioConfig`/`Population` (classes by rank, receiver bias), `PaymentStream` (hourly
    Poisson, alias tables, lognormal + truncated Pareto), `Outage` (unavailability with burst
    resubmission), `toml_lite`.
  - Test: `cargo test -p loopsettle-sim`; benchmark
    `cargo run --release -p loopsettle-sim --example bench_stream`.
- [x] Phase 4 — Calibration with public data
  - Done: `data/fetch_pix.py` (Olinda; the server does not accept `$skip` → a single request with
    a truncation check), `data/calibration/pix.toml` (Sep 2026), `loopsettle_sim::calibrate`, CLI
    `experiment calibration`, `ScenarioConfig::from_doc`.
  - Test: `cargo run --release -p loopsettle-cli -- experiment calibration` (all errors ≤ 1.5%;
    table in [`docs/PARAMETERS.md`](docs/PARAMETERS.md)).
- [x] Phase 5 — Alternative engines
  - Done: `DeferredNet` (O(n) deltas), `AtomicMicroCycle` (FIFO queues per edge, bounded DFS,
    atomic `try_batch`, exact deadlines, `QueueAll`/`QueueOnShortfall` modes),
    `loopsettle_sim::runner` (several engines in one pass, specs `gross`, `deferred:N`,
    `micro:all|shortfall:window:delay[:len]`), in-house SVG charts.
  - Test: `cargo test -p loopsettle-core` (invariants 1–5, 7 on the engines; DeferredNet 1×/day =
    LB); curve: `cargo run --release -p loopsettle-cli -- experiment microcycle-sweep` →
    `results/microcycle-sweep/{sweep.csv,shortfall.csv,fig_tradeoff.svg,summary.json}`.
  - Preliminary finding: with unlimited liquidity, micro-cycles (≤10 s) settle up to 63% of value
    in cycles but save ≤0.015% of UB; in the calibrated scenario LB/UB ≈ 0.91.
- [x] Phase 6 — Reproducible experiments
  - Done: `experiment {calibration, baseline, potential-vs-realizable, microcycle-sweep, stress,
    finland-replication}` → `results/<name>/` (CSV + `summary.json` with seed, code version,
    command, peak RAM; SVGs).
  - Main numbers (seed 20260930, 1M payments, 200 participants):
    - UB = R$ 71.27 M; LB = R$ 64.67 M (LB/UB = 0.91); gross volume R$ 443 M.
    - BCB-style potential = 0.854; potential end-of-day saving (UB−LB)/UB = 9.27%.
    - Gross ladder: Hodge L1 1.18 > CDFD 0.83 > cycles 0.80; net: Hodge L2 0.98 ≫ CDFD 0.17 >
      cycles 0.14.
    - Realizable: best micro-cycle (w500, d10s) saves 0.0147% of UB while settling 63% of value
      in cycles; DeferredNet every 10 s: 0.028%; every 15 min: 0.32%.
    - Finland: instant / 1 cycle per day = 1.10× (σ=0.4) to 1.50× (σ=0).
    - Stress (largest participant offline for 30 min): negligible effect on total UB.
